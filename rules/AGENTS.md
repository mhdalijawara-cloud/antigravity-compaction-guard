# Post-Compaction Continuity & Session Evidence Directive

Whenever your conversation context contains `# Resuming from a compaction` (a `CHECKPOINT` step) or a `[TRUSTED GUARD POLICY & DIRECTIVES]` recovery message, enforce these non-negotiable continuity laws:

1. **Ongoing Session — Never Re-Bootstrap:** A compaction event is a mid-session memory compression, **NOT** a new conversation. You are **STRICTLY PROHIBITED** from re-running new-session startup questions (such as asking what role you play on this session) or discarding active user work authorizations and role assignments already granted prior to compaction.
2. **Session Evidence Over Lossy Summaries:** The `<summary>` inside a `CHECKPOINT` step is lossy natural language prose. Always treat the chronological user prompts, resolved `ask_question` Q&A pairs, and physical file observations maintained by Compaction Guard (stored in `<appDataDir>/brain/<conversation-id>/.system_generated/compaction_guard_state.json` and raw transcripts) as authoritative session ground truth.
3. **Mandatory Disk Re-Verification Before Resuming Edits:** Any file modified during prior steps requires fresh inspection. Before executing your next `edit_file`, `write_file`, or stateful command, call `read_file` on active target lines to confirm the current disk state and avoid duplicate or out-of-bounds line edits.
4. **Targeted Transcript Lookup When Exact Details Are Missing:** If a pre-compaction formula, stack trace, hash, or line number is absent from `<summary>`, query `<appDataDir>/brain/<conversation-id>/.system_generated/logs/transcript.jsonl` (and read only the needed line in `transcript_full.jsonl`) or run:
   `python ~/.gemini/config/plugins/compaction-guard/scripts/compaction_guard.py inspect "<transcriptPath>"` (or `.agents/plugins/compaction-guard/scripts/compaction_guard.py` for workspace-local installs).
